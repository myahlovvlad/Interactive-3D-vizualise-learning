# MASTER PROMPT — Codex

Работай с существующим Interactive-3D-vizualise-learning как системный архитектор и инженер научного ПО. Цель: завершённый LAB-008 HS-GC-FID, не массовая генерация платформы. Прочитай README и все docs данного комплекта. ADR 001–122 утверждены. Не изменяй их без новой записи ADR. Сохрани исходные формулировки пользователя, если доступны. Документы — стартовая спецификация, не свидетельство реализации.

1. VS-00: проверь git status, ветку, структуру, исходный код, зависимости, тесты, лицензии, исходники Colorfigures и ресурсы. Не уничтожай пользовательские изменения и не выполняй массовый рефакторинг. Выдай baseline report: working/partial/stub/obsolete/unverified/missing. Если отсутствуют данные/движок, обозначь blocker и предложи законный адаптер. Не выдумывай исходники и проверочные данные. Зафиксируй lockfiles и минимальный воспроизводимый build.
2. Используй docs/scope.md и backlog.csv как базовый план P0; уточни только фактические зависимости и операциональные критерии в G0; расширения P1/P2 отдели. Resolve contradictions explicitly (G16 confirmation, uncertainty, three quantitative methods, dual renderer, protected assessment vs offline). Не сокращай утверждённый итоговый workflow скрытно. Создай полный реестр требований и дополни traceability.csv до покрытия каждого P0. У каждого требования ID, criterion, test, gate and status. Не создавай пустые пакеты.
3. Реализуй VS-01…07 последовательно, начиная с минимальной воспроизводимой хроматограммы. Каждый срез: contract → real implementation → integrated user path → positive/negative tests → evidence → documentation. Не переходи через блокирующий gate. В текущем цикле выполни VS-00 и подготовь исполнимый VS-01; продолжение только в пределах поставленной задачи и реальных ресурсов.
4. Scientific core: реализуй equations in science.md, units and provenance. Independent analytical/Python/Julia references with committed fixtures, convergence and conservation. Separate synthetic, simulated, imported. No fake validation or hardcoded output. Full workflow in workflow.md. Raw signal immutable; SST failures and unsupported identity block valid conclusion. Record uncertainty, rule version, seed streams and experiment artifacts.
5. Renderers share graph and snapshot; implement actual interaction, not screenshots. No scientific calculation inside renderer. Test ports, mounts, motion, occlusion, scale, 360°, mobile and fallback. Optional external solver only. 8GB laptop: one worker and serial tests; no mandatory Docker, database server or local LLM. Profile actual memory, do not claim physical performance based on CI alone.
6. Education: diagnostic prerequisites, tutorial/practice, numeric/spatial tasks, hints, transfer and evidence rubric. AI optional; no client-side claim of secure hidden answers. Provide accessible text paths.
7. Release: follow release.md. For each changed file classify intended/incidental; inspect exact diff, run final tests, retain command/output/commit/environment/seed/artifact hashes. Record untested claims and failed checks. Independent audit cannot be replaced by agent narrative. Human acceptance separate; do not invent signatures. No release claims if blocker; synthetic training scope clearly marked.
8. Output: baseline, updated docs, traceability, backlog with acceptance tests, actual changed files, commands and results, blockers, risks, gate status, next actionable slice. Do not present roadmap as completed functionality. Use small commits or proposed diffs according to user permissions; no force push, secret exposure or destructive operations.

9. Read docs/scope.md, docs/implementation.md, backlog.csv and docs/evidence-template.md. Run tools/check_baseline.py. It checks documentation consistency only, not product quality. Do not mark any task DONE before attaching actual evidence.
